# Publish the repository

1. Sign into your own GitHub account.
2. Create a repository named `prity-gtm-lab`. Public visibility lets application reviewers inspect it. Use the description from APPLICATION_KIT.md. Do not initialise another README or licence if uploading this folder.
3. Upload the extracted contents, including `src`, `demo`, `tests`, `agents`, `docs`, `projects`, `scripts`, `index.html`, `package.json`, README and LICENSE. Do not upload the ZIP itself as your source.
4. Include `.gitignore` and `.github` as well; file pickers may hide names starting with a dot. No `.env` secrets are included in this package, only `.env.example`.
5. Use an honest first commit message such as “Add initial GTM Lab prototypes and documentation.” Do not backdate contributions.
6. Pin the repository on your profile. To show the profile README, create a public repository with the exact same name as your username, and use docs/PROFILE_README.md as its README.md. Preserve any existing profile content.
7. Optionally enable GitHub Pages from the main branch root after publication; the root `index.html` is self-contained. Confirm the resulting live URL before adding it to the README or application.
8. Verify the repository and demo while signed out. Submit your profile URL in the application’s Github field.

## Terminal path, if you already have GitHub authentication configured

Open a terminal inside the extracted `prity-gtm-lab` folder. Run `git init`, `git add .`, and `git commit -m "Add initial GTM Lab prototypes and documentation"`. Create the empty remote repository in GitHub, then use the exact remote commands GitHub shows you. Do not paste an access token into a remote URL or chat.

## Things still requiring your account

A local package is not a live GitHub repository. Profile changes, repository creation, pinning and Pages must be verified in your signed-in account before claiming publication. This project includes no fabricated profile URL or pretend live deployment.
