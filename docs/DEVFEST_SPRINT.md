# A focused three-hour contribution

## Goal

Turn the included ADK integration into a verified, documented agent workflow and submit one reviewable pull request. Bring the offline prototype as a baseline. Tell the organisers it was prepared before the event and ask what counts toward their submission; do not present prebuilt work as completed during the sprint.

| Minutes | Work | Reviewable output |
| --- | --- | --- |
| 0–20 | Show the baseline, explain the problem, agree scope with a mentor | One issue with acceptance criteria |
| 20–65 | Set up ADK, confirm model access and tool calls | Successful fictional example and captured versions |
| 65–110 | Test opt-outs, negative availability and ambiguous intent; fix one issue | Regression case and implementation change |
| 110–145 | Evaluate ten newly written examples and inspect failures | Results with denominators and error examples |
| 145–165 | Update docs and check the demo | Setup instructions another attendee can follow |
| 165–180 | Open PR and demonstrate the change | PR description and 90-second walkthrough |

Fallback if model access or Python setup blocks progress: improve indirect opt-out handling or add a batch review view locally. Submit that tested change honestly. Do not spend the whole sprint configuring credentials.

## Ask mentors

- Does this Agent Development Kit project fit the event's Google open-source scope?
- Is a contribution to my own new repository eligible, or must we contribute to a designated project?
- Is a prebuilt baseline permitted if the sprint contribution is clearly separated?
- How can I enforce output restrictions beyond prompt wording?

## Acceptance criteria

- A new contributor can reproduce the change.
- No actual LinkedIn account is required for the demo.
- Evidence and uncertainty remain visible.
- No message is sent or scheduled.
- The PR records tests, failures and remaining limitations.
